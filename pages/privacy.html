// Overview

✓ SentryEye's developers have ZERO access to your personal data, device contents, or usage patterns. This is an architectural guarantee, not a policy promise.

SentryEye is a local-first Android security application. Its core operations — intruder capture, threat logging, PIN monitoring, and security alerting — execute entirely within the boundaries of your device. No data is routed through, stored on, or processed by servers owned or operated by the SentryEye developer.

This privacy policy explains what data exists, where it lives, who can access it (you), and the narrow circumstances under which any external service is involved.

// Information Collection

The SentryEye developer collects no personal information whatsoever. There is no account system, no registration, no email capture, and no telemetry pipeline connected to any developer-controlled server.

Data generated by the application's security functions — including:

  • Front-camera images captured on failed authentication attempts
  • Timestamped security event logs and threat records
  • Biometric verification audit trails
  • System resource and battery usage diagnostics

...is stored exclusively in an AES-256 encrypted Room database on your device's internal storage. It is not transmitted, replicated, or accessible to any entity other than the device owner.

// Local Data Storage

All persistent application data is stored in a SQLite database managed by Android's Room persistence library. This database:

  • Is encrypted at rest using AES-256 via SQLCipher for Android
  • Resides in your device's private application storage sandbox
  • Is inaccessible to other applications due to Android's process isolation model
  • Is removed entirely upon application uninstall
  • Is never included in standard Android cloud backup (android:allowBackup="false")

You retain full, exclusive control over this data. You may view, export, or permanently delete it at any time from within the application's Settings screen.

// User Analytics

⚠ SentryEye uses anonymous, non-identifiable crash reporting. No personal data, device identifiers, or security data is ever included.

SentryEye uses a privacy-preserving crash analytics service to detect application stability issues. This service is configured with the following strict constraints:

  • Collection is limited to anonymous stack traces and error codes
  • Device identifiers (IMEI, Android ID, advertising ID) are explicitly excluded
  • No security data, capture images, or log entries are ever transmitted
  • IP addresses are not logged or stored by the analytics provider
  • Data is used exclusively for crash diagnosis and performance optimization

Crash reporting can be disabled at any time in Settings → Privacy → Crash Reporting. Disabling it does not affect any core security functionality.

// Third-Party Cloud (Google Drive)

SentryEye offers an optional encrypted backup feature that connects directly to your personal Google Drive account. The implementation details:

  • Authentication uses Google OAuth 2.0 with the narrowest possible scope (drive.file)
  • The OAuth flow is handled entirely between your device and Google's authorization servers
  • SentryEye requests access only to files it creates — not your full Drive contents
  • Backup data is AES-256 encrypted on-device before any transfer begins
  • The encrypted backup travels directly from your device to your Google Drive
  • No SentryEye-operated server is in the data path at any point
  • OAuth tokens are stored locally in Android's EncryptedSharedPreferences

Google's handling of data transmitted to their services is governed by Google's own Privacy Policy. SentryEye has no visibility into or control over data once it is stored in your Google Drive.

// App Permissions

SentryEye requests the following Android permissions, each with an explicit justification:

  • CAMERA — Required for front-camera intruder capture on PIN failure. Used only when the threshold is triggered.
  • USE_BIOMETRIC — Required for biometric unlock integration. Evaluation occurs in Android's Biometric API sandbox.
  • INTERNET — Required only for the optional Google Drive sync feature. Not used otherwise.
  • RECEIVE_BOOT_COMPLETED — Required to re-arm the security monitor after device restart.

No other permissions are requested. The application manifest declares no unnecessary permission groups.
